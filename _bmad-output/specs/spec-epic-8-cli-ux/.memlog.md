- (capability) CAP-1: User reviews Foundry's interpretation of their spec before any phase executes and approves intent, not output. Success: readback appears before phase 1; user can abort and edit spec before approving; --yes bypasses gate but still prints readback.
- (capability) CAP-2: When Foundry fails, exit output names the failing phase, story, and reason. Success: final stderr line matches [phase/story] failed: <reason> format; agent timeout, non-zero exit, and output validation failure are distinguished.
- (capability) CAP-3: At every phase boundary Foundry prints what completed and what comes next, then waits for keypress before proceeding. Success: every boundary shows summary; --yes/CI skips wait; signal fires even before the final phase.
- (constraint) --yes / non-interactive mode bypasses both the readback gate (CAP-1) and the phase-signal wait (CAP-3) without human intervention; readback is still printed to stdout.
- (constraint) Once the run begins (after readback approval), it runs to completion or a named failure — no mid-run checkpoints added by this epic.
- (constraint) Quick mode (Epic 7, --yes flow) must not break; phase signal fires at quick-mode phase boundaries if they exist.
- (constraint) Readback content parses the spec/idea string; it does not modify RunContext or lock state.
- (decision) Non-goals: web dashboard, mid-run checkpoints, decorative progress indicators (spinners/bars without signal), inline diff review at checkpoint.
- (decision) Design north star from brainstorm: authorship, not relief. Spec is the control surface. Emotional target: user feels like the author, not a passenger.
- (decision) Stories: 8.1 Spec Interpretation Readback (CAP-1), 8.2 Named Failure States (CAP-2), 8.3 Phase Signal (CAP-3). Test target ~950 from baseline 867.
- (event) Self-validate Pass 1 (Coherence): all 3 CAPs have intent+success; constraints rule out mid-run gates and decoration; 5 open questions from PRD addendum carried forward. Pass 2 (Preservation): all load-bearing PRD claims absorbed.
- (event) stories.yaml written: 3 stories (8-1 spec readback, 8-2 named failures, 8-3 phase signal). Validity check: ids unique, no zero-padding, no status field, strings quoted. All required fields present.
