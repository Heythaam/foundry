- (decision) AD-1: Pipes-and-filters paradigm - each phase is a filter that reads an artifact and produces the next, connected by the orchestrator pipeline
- (decision) AD-2: Foundry core owns orchestration only - never imports phase-specific logic directly; phases are callables behind a Phase protocol
- (decision) AD-3: All state mutations go through two sinks: LockfileWriter (foundry.lock TOML) and ForgeLog (git commits). No silent state changes.
- (decision) AD-4: Failure classifier sits between every external call and the orchestrator - classifies before bubbling, never lets raw exceptions reach phase logic
- (decision) AD-5: Checkpoint protocol is a single interface - and web UI are two implementations of the same CheckpointHandler protocol
- (decision) AD-6: aiosqlite is internal WAL only - buffers in-flight state between atomic foundry.lock writes, never committed, .gitignored
- (decision) AD-7: One Claude Code subprocess per story - no session reuse, no shared context between stories, clean isolation
- (decision) AD-8: foundry.lock is append-structured TOML - sections are added, never edited in place; prevents merge conflicts on epic branch merges
- (decision) AD-9: Git operations go through a GitOps adapter wrapping PyGitHub (remote) and subprocess git (local) - single owner of all repo mutations
- (decision) AD-10: Planning pipeline runs in a local temp workspace; repo creation is a one-time transition that copies artifacts into the scaffold commit
- (event) Architecture spine v1 drafted: 10 ADs, pipes-and-filters paradigm, full structural seed with 3 diagrams
- (decision) AD-7 detail: Claude Code SDK invoked via Python API with working dir set to repo root. Story prompt assembled as a temp markdown file in .foundry/ containing story text, acceptance criteria, and architecture doc content. SDK reads/writes files in the working dir directly. No stdin piping.
- (decision) AD-6 detail: Crash recovery - on resume, check git status for uncommitted changes. If dirty: run test runner. If green, commit as the interrupted story and continue. If red, git checkout to discard and re-run the story from scratch. StateBuffer rebuild: read foundry.lock for completed stories, derive next story from manifest.
